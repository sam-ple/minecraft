【Minecraft 複数ワールド運用時の注意点】

■ ワールドについて
・ワールドを増やしただけでは、大きな負荷にはなりにくい
・誰もいないワールドは基本的にプレイヤーがいるワールドほど処理されない
・forceload等でチャンクを常時ロードすると負荷になる
・Mob、アイテム、アーマースタンド等を大量に残さない

■ Skriptについて
・Skriptはサーバー全体で動作する
・ワールドを追加しても、Skriptがワールドごとに別起動するわけではない
・「on join」「on death」「on damage」などのイベントは全ワールドが対象になる
・「every 1 second」などの定期処理もサーバー全体で動作する

■ ゲーム用Skriptの注意
・ゲーム専用処理にはワールド判定を入れる
・例：
if player's world is world("tetsusen"):
...

・ゲーム終了時には以下をリセットする
・Mob
・落ちているアイテム
・ゲーム変数
・タイマー
・スコア
・プレイヤーの状態

■ ワールド構成の例
world
→ 通常ワールド

lobby
→ 最初に入る場所
→ ゲーム選択

tetsusen
→ 鉄千

linerace
→ LINE RACE

jinro
→ 人狼

■ 基本方針
「ワールドはゲームごとに分ける」
「Skriptはワールド条件を付けて必要な場所だけ処理する」
「ゲーム終了時にゲーム内のものをリセットする」

この構成なら、ゲームを追加していっても比較的管理しやすい。

============================================================
Multiverse-Core コマンド一覧
============================================================

【ワールド確認】

/mv list
    → 現在登録されているワールド一覧を表示


【ワールド作成】

/mv create <ワールド名> normal
    → 通常ワールドを新規作成

例：
/mv create tetsusen normal


【既存ワールドを登録】

/mv import <ワールド名> normal
    → 既に存在するワールドをMultiverseに登録

例：
/mv import lobby


【ワールド削除】

/mv remove <ワールド名>
    → Multiverseの管理対象から外す
    ※ワールドのデータ自体を削除するものではない

例：
/mv remove tetsusen


【ワールドへ移動】

/mvtp <ワールド名>
    → 自分を指定ワールドへ移動

例：
/mvtp lobby
/mvtp tetsusen


【指定プレイヤーを移動】

/mvtp <プレイヤー名> <ワールド名>

例：
/mvtp crocado tetsusen


【全員を移動】

Multiverse-Core単体の操作より、Skriptから実行するのが便利。

loop all players:
    execute console command "mvtp %loop-player% lobby"

→ オンラインの全員をlobbyへ移動


【ワールドのスポーン地点】

/mv set spawn

    → 現在地を、そのワールドのスポーン地点に設定


【ワールド情報】

/mv info <ワールド名>

例：
/mv info lobby

    → ワールドの各種設定を確認


【ワールドの環境】

/mv modify set <設定> <値> <ワールド名>

例：
/mv modify set pvp false lobby

    → lobbyでPvPを無効化


【ワールドのゲームモード】

/mv modify set gamemode adventure lobby

    → lobbyをAdventure Modeに設定


【ワールドの難易度】

/mv modify set difficulty peaceful lobby

    → lobbyをPeacefulに設定


【ワールドの天候】

/mv modify set weather false lobby

    → 天候変化を無効化


【ワールドの時間】

/mv modify set time 6000 lobby

    → lobbyの時間を設定


【ワールド削除時の注意】

/mv remove <world>
    ↓
Multiverseから登録解除

これは基本的に「ワールドフォルダを完全削除」ではない。

不要なワールドを完全に消す場合は、
サーバー停止後にワールドフォルダを削除する。

============================================================
Skript 運用時の注意点
============================================================

■ 1. ワールド判定を入れる
ゲーム専用処理は、基本的に対象ワールドを限定する。

例：

if player's world is world("tetsusen"):
    ...


------------------------------------------------------------

■ 2. every 処理に注意

every 1 tick:
every 1 second:

などは、プレイヤーがいなくても処理自体は動く。

ゲーム中だけ動かしたい処理は、

if {tetsusen.running} is true:
    ...

のようにゲーム状態で止める。


------------------------------------------------------------

■ 3. on death などのイベントは全ワールドが対象

on death:
    ...

だけだと、lobbyやworldでの死亡も拾う。

必要なら、

if victim's world is world("tetsusen"):
    ...

とする。


------------------------------------------------------------

■ 4. プレイヤーがいないゲームは処理しない

ゲーム終了時に、

{tetsusen.running} = false

などにして、タイマー・判定・スポーン処理を停止する。


------------------------------------------------------------

■ 5. ゲーム終了時に必ずリセットする

・ゲーム変数
・タイマー
・スコア
・Mob
・アイテム
・BossBar
・Scoreboard
・プレイヤー状態
・ゲーム中フラグ

などをリセットする。


------------------------------------------------------------

■ 6. loop all players に注意

loop all players:
    ...

はサーバーにいる全員が対象。

ゲーム参加者だけを対象にするなら、

loop {tetsusen.players::*}:
    ...

など、参加者リストを使う。


------------------------------------------------------------

■ 7. コマンド実行の多用に注意

Skriptから、

execute console command "..."

を大量に毎tick実行するのは避ける。

可能ならSkriptの機能を直接使う。


------------------------------------------------------------

■ 8. 変数名をゲームごとに分ける

悪い例：

{running}
{time}
{players::*}

良い例：

{tetsusen.running}
{tetsusen.time}
{tetsusen.players::*}

こうするとゲーム同士の変数衝突を防げる。


------------------------------------------------------------

■ 9. reload時の状態に注意

/reload や

/sk reload xxx

をすると、ゲーム途中の状態とSkript側の状態が
一致しなくなる場合がある。

開発中はreloadしても、
本番ではなるべくゲーム停止 → reload → 初期化
の順番にする。


------------------------------------------------------------

■ 10. エラーを放置しない

Skript reload時に、

Can't understand this expression
Can't compare
Can't set
...

などが出た場合は、そのまま使わない。

一見動いていても、その部分だけ処理されていない可能性がある。


============================================================
使わないSkriptはdisableした方がいい？
============================================================

基本的には、

「使わないゲームのSkriptはdisableしておく」

でOK。

特に開発中のゲームが多いならおすすめ。


例：

tetsusen.sk       → 有効
linerace.sk       → 有効
jinro.sk           → 有効
advancement.sk    → 無効
test.sk            → 無効


------------------------------------------------------------

ただし、

「ファイルを置いているだけ」
「Skriptとして読み込まれているだけ」

なら、それだけで大きな負荷になるわけではない。

問題になるのは、

every 1 tick:
every 1 second:
大量のイベント処理
大量のloop
大量のコマンド実行

など。


------------------------------------------------------------

おすすめ

開発中
↓
使わないゲーム → disable

完成後
↓
使うゲーム → enable
使わないゲーム → disable

これで管理する。


============================================================
Skript コマンド一覧
============================================================

【基本】

/sk
    → Skriptのヘルプ


/sk reload <ファイル名>
    → 特定のSkriptをreload

例：
/sk reload tetsusen


/sk reload all
    → 全Skriptをreload


/sk disable <ファイル名>
    → 特定のSkriptを無効化


/sk enable <ファイル名>
    → 特定のSkriptを有効化


/sk scripts
    → 読み込まれているSkript一覧


/sk version
    → Skriptのバージョン確認


/sk info
    → Skriptの情報確認


/sk help
    → ヘルプ


============================================================
開発時によく使うもの
============================================================

/sk reload tetsusen

    ↓

tetsusen.skだけ再読み込み


/sk reload linerace

    ↓

linerace.skだけ再読み込み


/sk disable tetsusen

    ↓

tetsusen.skを無効化


/sk enable tetsusen

    ↓

tetsusen.skを有効化


/sk scripts

    ↓

現在のSkript状態を確認


============================================================
おすすめのファイル構成
============================================================

plugins/Skript/scripts/

    lobby.sk
    tetsusen.sk
    linerace.sk
    jinro.sk
    advancement.sk

    test/
        test_death.sk
        test_world.sk


本番で使わないものはdisable。


============================================================
重要
============================================================

「Skriptファイルが存在する」
        ↓
負荷が大きい

ではない。

「読み込まれていて、イベントやevery処理が動いている」
        ↓
負荷になる可能性がある。


特に注意するのは、

every 1 tick
every 5 ticks
every 10 ticks
大量のloop
大量のexecute console command
大量のentity検索

このあたり。


基本方針：

「ゲームごとにSkriptを分ける」
「ゲーム処理にはワールド判定を入れる」
「ゲーム停止時は定期処理も止める」
「使わないゲームはdisable」
「ゲーム変数にはゲーム名を付ける」

これでかなり安全に拡張できる。
