============================================================
Minecraft ミニゲームサーバー
ワールド削除・再生成時のSkriptデータ管理 注意点
===========================

■ 基本原則

Minecraftの「ワールド」とSkriptの「データ」は別物。

ワールドを削除して新しいワールドを作成しても、
Skriptの変数は自動的には削除されない。

つまり、

```
ワールド削除
    ↓
新規ワールド作成
```

だけでは、前回ゲームのSkriptデータが残る可能性がある。

---

■ 1. ワールドを削除してもSkript変数は残る

例えばLINERACEで、

```
{linerace.start}
{linerace.players::*}
{linerace.score::*}
{linerace.running}
```

などを使用していた場合、

```
ワールド削除
    ↓
新しいLINERACEワールド作成
```

としても、これらのSkript変数は自動的には消えない。

特にプレイヤーUUIDをキーにした変数には注意。

例：

```
{linerace.score::%uuid of player%}
```

このようなデータはワールドとは無関係なので、
ワールドを削除しても残る。

---

■ 2. 「RESET」と「ワールド削除」は別の処理として考える

ゲーム終了時は、

```
STOP
    ↓
RESET
    ↓
ワールド削除
    ↓
新規ワールド作成
```

という考え方にする。

RESETは、

「次のゲームを完全な初期状態から開始できる状態にする」

ための処理。

ワールド削除は、

「前回のステージそのものを消す」

ための処理。

この2つは目的が違う。

---

■ 3. RESETではゲーム固有のSkript変数を削除する

例えばLINERACEなら、

```
delete {linerace.start}
delete {linerace.players::*}
delete {linerace.score::*}
delete {linerace.running}
```

など、

LINERACEが使用した一時データをすべて削除する。

重要なのは、

「ゲームで作った変数を最初から一覧化しておく」

こと。

ゲームを作るときに、

```
【永続設定】
【ゲーム状態】
【一時データ】
【プレイヤーデータ】
```

などを整理しておくと、RESETを作りやすい。

---

■ 4. Skript変数以外にもゲーム終了時に残るものがある

ゲームで変更したものは、Skript変数だけではない。

例えば、

```
・Scoreboard
・Team
・Tag
・Gamemode
・Spawnpoint
・プレイヤーの位置
・インベントリ
・Potion Effect
・特殊な状態
・ゲーム用のEntity
・ゲーム用のBlock
・ワールド設定
```

など。

これらも必要に応じてゲーム終了時に元へ戻す。

---

■ 5. 特にプレイヤー関連データに注意

ゲームで、

```
{game.score::%uuid of player%}
```

のようなデータを使用する場合、

ワールドを削除してもプレイヤーUUIDは変わらない。

そのため、

```
前回ゲーム
    ↓
プレイヤーA = 100点
    ↓
ワールド削除
    ↓
新しいゲーム
    ↓
プレイヤーA = 100点が残っている
```

という事故が起こり得る。

ゲーム開始時に初期化する方法と、
ゲーム終了時に削除する方法の両方を検討する。

---

■ 6. 「START時にも初期化する」とさらに安全

RESETだけに頼らず、

```
START
    ↓
ゲームデータ初期化
    ↓
新しいゲーム開始
```

とするのも安全。

例えば、

```
START
    ↓
前回の参加者情報を削除
    ↓
前回のスコアを削除
    ↓
ゲーム状態を初期化
    ↓
今回のゲーム開始
```

とする。

こうすると、RESETを実行し忘れた場合でも
古いデータがゲームに混入する危険を減らせる。

---

■ 7. 「完全初期化」をゲームごとに定義する

各ゲームには、

```
RESET = 完全初期化
```

というルールを作る。

例えばLINERACEなら、

```
/line reset
```

を実行した時点で、

```
・ゲーム状態
・参加者
・スコア
・順位
・スタート地点
・ゴール状態
・一時変数
・Scoreboard
・Team
・Tag
・ゲーム用Entity
・必要なプレイヤー状態
```

などを整理する。

---

■ 8. ワールドとゲームデータを完全に分離する

理想的な構造は、

```
ゲームシステム
    │
    ├── Skriptデータ
    │     ├── ゲーム状態
    │     ├── プレイヤー
    │     ├── スコア
    │     └── 設定
    │
    └── Minecraftワールド
          ├── ステージ
          ├── ブロック
          ├── Entity
          └── プレイヤー位置
```

と考える。

ワールドを消すことでステージを完全消去し、
SkriptのRESETでゲームデータを完全消去する。

---

■ 9. MineScriptとSkriptの役割分担

現在の構成では、

```
MineScript
    ↓
ステージ生成・ワールド構築

Skript
    ↓
ゲーム進行・プレイヤー管理・スコア・順位
```

という分業が適している。

例えば、

```
MineScript
    ・コース生成
    ・建築
    ・スタート地点作成
    ・装飾
    ・ステージ配置

Skript
    ・START
    ・STOP
    ・RESET
    ・参加者管理
    ・スコア
    ・順位
    ・ゲーム状態
    ・結果表示
```

とする。

---

■ 10. 今後ゲームを増やす場合の重要ルール

ゲームごとに変数の名前を分ける。

悪い例：

```
{score}
{players::*}
{start}
{running}
```

複数ゲームで同じ変数を使うと、
別ゲームのデータと衝突する可能性がある。

良い例：

```
{linerace.score::*}
{linerace.players::*}
{linerace.start}
{linerace.running}

{orerace.score::*}
{orerace.players::*}
{orerace.running}

{farrace.distance::*}
{farrace.players::*}
{farrace.start}
```

のようにゲーム名をPrefixとして付ける。

---

■ 11. ゲームごとに「所有物」を決める

各ゲームについて、

「このゲームが作ったものは何か？」

を最初に決めておく。

例：

LINERACE

```
Skript
├── {linerace.*}

Minecraft
├── LINE用Block
├── Start地点
├── Goal地点
├── Team
└── Scoreboard
```

RESETでは、
これらをLINERACE自身が責任を持って片付ける。

---

■ 12. 理想的なゲームのライフサイクル

新しいゲームを作るときは、
基本的に以下の流れを標準化する。

```
INIT
  ↓
SET
  ↓
START
  ↓
GAME
  ↓
STOP
  ↓
RESET
  ↓
WORLD DELETE
  ↓
WORLD CREATE
  ↓
SET
  ↓
START
```

これを全ゲームで統一すると、
ゲーム数が増えても管理しやすい。

---

■ 13. 最も重要な考え方

「ワールドを作り直したから、ゲームもリセットされた」

とは考えない。

正しくは、

```
ワールド
    = ステージ・ブロック・Entityなどの世界データ

Skript
    = ゲーム状態・スコア・参加者などの管理データ
```

と考える。

したがって、

```
ワールドの初期化
    +
Skriptの初期化
    +
プレイヤー状態の初期化
```

この3つを揃えて、

```
「ゲームの完全リセット」
```

とする。

---

■ 今後の開発方針

今後ゲームを作るときは、最初に

```
1. 使用するSkript変数
2. ゲーム中に変更するMinecraft側の状態
3. ゲーム終了時に戻すもの
4. RESETで削除するもの
5. ワールド削除で消えるもの
6. 新規ワールド生成時に再作成するもの
```

を整理してから実装する。

これを最初に決めておくと、

```
「前のゲームのスコアが残っている」
「前回のTeamが残っている」
「前回のプレイヤーが参加者扱いになっている」
「前回のScoreboardが残っている」
「新しいワールドなのに古いゲーム状態になっている」
```

といったバグを大幅に減らせる。

============================================================
結論

ワールド削除 ≠ ゲーム完全リセット

ゲーム完全リセットには、

```
【ワールド】
→ 削除・再生成

【Skript】
→ 変数・ゲーム状態をRESET

【プレイヤー】
→ Team・Scoreboard・状態などをRESET
```

の3つを意識する。

今後のミニゲーム開発では、

```
RESET = 「次のゲームを完全に新規状態で開始できる状態」
```

# として設計するのが安全。
