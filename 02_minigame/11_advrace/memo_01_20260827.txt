ADVANCEMENT RACE GAME SYSTEM
Minecraft Java Edition + Paper + Skript

============================================================

1. ゲーム概要
   ============================================================

Minecraftの「進捗（Advancement）」を利用した取得レースゲームを作成する。

プレイヤーが進捗を取得すると、その進捗に応じてポイントを獲得する。

制限時間内にできるだけ多くの進捗を取得し、最終的なポイントでランキングを競う。

既存のMinescript版「ADVANCEMENT RACE GAME SYSTEM」を参考にするが、最終的にはSkriptのみで動作するシステムとして作り直す。

============================================================
2. 基本ルール
========

ゲーム開始後、プレイヤーがMinecraftの進捗を取得すると自動的に検知する。

進捗取得者本人にポイントを与える。

Minecraftの仕様上、通常の進捗は一度取得すると再取得できないため、同一プレイヤーによる同一進捗の重複ポイント防止は基本的には不要。

「進捗を取得した回数」ではなく、「取得した進捗の種類」と「進捗の種類によるポイント」で競争する。

============================================================
3. ポイントシステム
===========

基本ポイントは1ポイント。

通常の進捗：
+1 point

「ゴール（Goal）」タイプ：
+2 point

「チャレンジ（Challenge）」タイプ：
+3 point

必要に応じてFIRST BONUSを追加できる。

FIRST BONUS：
ゲーム中、最初にその進捗を取得したプレイヤーに+1 point。

FIRST BONUSはON/OFF可能にする。

============================================================
4. FIRST BONUS
==============

FIRST MODEがONの場合、ゲーム中に初めて特定の進捗を取得したプレイヤーに+1ポイント。

例：

Aが「石器時代」を最初に取得
→ 通常ポイント + FIRST BONUS
→ 合計2ポイント

その後Bが同じ進捗を取得
→ 通常ポイントのみ

BにはFIRST BONUSは付かない。

ゲーム開始時にFIRST取得履歴をリセットする。

============================================================
5. PICKUP MODE
==============

将来的にPICKUP MODEを実装する。

ゲーム開始時に指定された進捗の中から複数の進捗をランダムに選択し、PICKUP TARGETとして設定する。

PICKUP TARGETを取得した場合、通常ポイントに+1 BONUS。

例：

通常進捗：
+1

PICKUP TARGET：
+1 BONUS

FIRST：
+1 BONUS

その場合、
合計3ポイントになる。

PICKUP MODEはON/OFF可能にする。

PICKUP TARGETはゲーム開始時にランダム決定する。

============================================================
6. Advancementの種類
=================

Minecraftの進捗には、

・Advancement
・Goal
・Challenge

などの種類が存在する。

Minecraftから取得した進捗情報を利用して、種類を判定する。

最終的には、

通常：
1 point

Goal：
2 points

Challenge：
3 points

として扱う。

ただし、Skriptで取得できる情報に制限がある場合は、実際に取得できるイベント情報を確認した上で実装方法を決定する。

============================================================
7. ゲームコマンド
==========

以下のコマンドを用意する。

/advrace start

ゲーム開始。

・ゲーム状態をRUNNINGにする
・ポイントを初期化
・FIRST取得履歴を初期化
・PICKUP TARGETを初期化
・タイマー開始
・BossBar表示
・ランキング用Scoreboard開始

/advrace stop

ゲーム停止。

・ゲーム状態をSTOPPEDにする
・タイマー停止
・ゲーム結果を必要に応じて表示

/advrace reset

ゲームデータを完全にリセットする。

・ポイント
・FIRST取得履歴
・PICKUP TARGET
・ランキング
・ゲーム状態

を初期化する。

/advrace restart

ゲームを再スタートする。

必要に応じて現在のゲーム状態を復元できる設計にする。

/advrace status

現在のゲーム状態を表示する。

・RUNNING / STOPPED
・残り時間
・各プレイヤーのポイント
・取得進捗数
・FIRST取得数
・PICKUP TARGET

などを確認できるようにする。

/advrace debug

DEBUG MODEのON/OFFを切り替える。

============================================================
8. DEBUG MODE
=============

開発中はDEBUG MODEを用意する。

DEBUG MODE ONの場合、進捗取得時に以下の情報を表示する。

Player
Advancement
Advancement ID
Advancement Type
Base Point
FIRST判定
PICKUP判定
Final Point

例：

[AdvRace DEBUG]
Player: crocado
Advancement: Stone Age
ID: minecraft:story/mine_stone
Type: Advancement
Base: +1
FIRST: YES
PICKUP: NO
Final: +2

通常時は大量のログを表示しない。

DEBUG MODE OFFの場合、必要最低限のゲーム通知のみ表示する。

============================================================
9. ログ
=====

ゲーム中に取得された進捗をログファイルに保存する。

ログには最低限、

・時刻
・プレイヤー
・進捗名
・進捗ID
・獲得ポイント
・FIRSTかどうか

を記録する。

例：

[01:23] crocado : Stone Age (+2) (FIRST)

DEBUG MODEの場合のみ、詳細情報をコンソールに出力する。

通常プレイ時に大量のログを出さない。

============================================================
10. Scoreboard
==============

ゲーム中はScoreboardを利用してプレイヤーごとのポイントを表示する。

例：

ADV RACE

crocado       18
Player2       15
Player3       11

============================================================
11. BossBar
===========

ゲーム開始時にBossBarを表示する。

BossBarには残り時間を表示する。

例：

ADVANCEMENT RACE
04:59

時間が経過するにつれて残り時間を減少させる。

時間切れになったらゲーム終了。

============================================================
12. ゲーム終了
=========

制限時間が0になったらゲームを終了する。

TIME UP演出を行う。

その後ランキングを表示する。

例：

ADVANCEMENT RACE RESULT

1. crocado : 32 pt
2. Player2 : 27 pt
3. Player3 : 21 pt

必要に応じて勝者演出を行う。

============================================================
13. データ管理
=========

プレイヤーごとに以下のデータを管理する。

ポイント
取得進捗数
取得進捗一覧
FIRST取得一覧

例：

{advrace.points::UUID}
{advrace.count::UUID}
{advrace.first::*}
{advrace.pickup::*}

============================================================
14. ゲーム開始時の初期化
==============

/advrace start実行時に、

・ポイント
・取得数
・FIRST履歴
・PICKUP TARGET
・タイマー

をゲーム用に初期化する。

ただし、Minecraft本体のAdvancement取得状態そのものを自動で全削除するかどうかは別途設定する。

既存の進捗を残した状態でゲームを行うモードと、開始時に全進捗をrevokeして新規ゲームとして行うモードの両方を将来的に検討する。

============================================================
15. 重要な設計方針
===========

最初から全機能を実装しない。

必ず段階的に開発する。

Phase 1：
進捗取得イベントをSkriptで検知できるか確認する。

Phase 2：
進捗名・進捗IDなどを取得できるか確認する。

Phase 3：
進捗取得時に+1ポイントできるか確認する。

Phase 4：
Scoreboardにポイントを表示する。

Phase 5：
Goal / Challengeなどの種類によるポイント差を追加する。

Phase 6：
FIRST BONUSを追加する。

Phase 7：
PICKUP MODEを追加する。

Phase 8：
BossBarタイマーを追加する。

Phase 9：
ランキング・終了演出・ログ保存を追加する。

============================================================
16. 最初の開発目標
===========

最初のミニテストでは、以下だけを実装する。

/advrace start
/advrace stop
/advrace reset
/advrace status
/advrace debug

ゲーム中にプレイヤーが進捗を取得したら、

1. 進捗取得イベントを検知
2. プレイヤーを取得
3. 進捗名を取得
4. 可能であれば進捗IDを取得
5. DEBUG MODEなら詳細表示
6. プレイヤーに+1ポイント
7. Scoreboardにポイント表示

これだけを確認する。

BossBar、FIRST BONUS、PICKUP MODE、Goal/Challengeによるポイント差、ランキング、ファイルログなどは最初のテストには実装しない。

最初の目的は、

「SkriptでMinecraftのAdvancement取得を確実に検知して、ポイントとして扱えることを確認する」

ことである。

============================================================
17. 実装上の注意
==========

Skriptのバージョンは実際にサーバーで使用しているバージョンを基準とする。

不確実なSkript構文を大量に使用しない。

まず最小構成でreloadできることを確認する。

エラーが出た場合は、そのエラーを確認してから次の機能を追加する。

特にAdvancement関連のイベント構文や取得可能な値は、使用しているSkriptバージョンで実際に確認する。

「最終仕様を一気に実装する」のではなく、「動作確認 → 機能追加」の順番で開発する。

============================================================
18. 最終目標
========

Minecraftに存在する多数のAdvancementを利用して、

「誰が最も効率よく進捗を獲得し、多くのポイントを稼げるか」

を競うレースゲームを完成させる。

既存のMinescript版ADVANCEMENT RACEの考え方を引き継ぎつつ、Skript版として管理・拡張しやすい構造にする。
