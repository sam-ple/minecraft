ORERACE GAME SYSTEM
Minecraft Java Edition + Paper + Skript

============================================================

1. ゲーム概要
   ============================================================

Minecraftの鉱石採掘を利用したポイントレースゲームを作成する。

ゲーム開始後、プレイヤーが対象となる鉱石を採掘すると、その鉱石の種類に応じてポイントを獲得する。

制限時間内にできるだけ多くの鉱石を採掘し、最終的なポイントでランキングを競う。

既存のMinescript版「ORERACE GAME SYSTEM」を参考にするが、最終的にはSkriptのみで動作するシステムとして作り直す。

============================================================
2. 基本ルール
========

ゲーム中にプレイヤーが対象鉱石を破壊した場合、その鉱石に設定されたポイントをプレイヤーに加算する。

対象鉱石は以下を基本とする。

Copper Ore
Iron Ore
Gold Ore
Lapis Lazuli Ore
Emerald Ore
Diamond Ore

Deepslate版も対象とする。

Deepslate Copper Ore
Deepslate Iron Ore
Deepslate Gold Ore
Deepslate Lapis Lazuli Ore
Deepslate Emerald Ore
Deepslate Diamond Ore

通常鉱石とDeepslate鉱石は同じポイントとして扱う。

4. 採掘判定
=======

対象鉱石をプレイヤーが実際に破壊した場合にポイントを与える。

ゲームがRUNNING状態の場合のみポイント対象とする。

ゲーム開始前の採掘はポイントにしない。

ゲーム終了後の採掘もポイントにしない。

============================================================
5. Fortune / 採掘量について
====================

ポイントは「鉱石ブロックを何個破壊したか」を基本とする。

Fortuneによってアイテムのドロップ数が増えても、ポイントは増加しない。

例：

Diamond Oreを1ブロック破壊
FortuneによってDiamondが3個ドロップ

→ +5 point

+15 pointにはしない。

============================================================
6. Silk Touchについて
=================

Silk Touchで鉱石ブロックそのものを取得した場合でも、鉱石ブロックを破壊した時点でポイントを与える。

例：

Silk Touch Diamond Ore
→ +5 point

============================================================
7. ダブルポイントタイム
=============

将来的にDOUBLE POINT TIMEを実装する。

ゲーム終了前の指定された時間をダブルポイント時間とする。

例：

ゲーム時間30分
DOUBLE TIME 30秒

残り30秒になるとDOUBLE POINT TIME開始。

通常：

Diamond Ore
+5

DOUBLE POINT TIME：

Diamond Ore
+10

DOUBLE POINT TIME開始時に全プレイヤーへ通知する。

例：

DOUBLE POINT TIME!

============================================================
8. ダブルポイントの対象
=============

DOUBLE POINT TIMEでは、鉱石の基本ポイントを2倍にする。

FIRST BONUSなど別のボーナスを追加する場合は、将来的に計算方法を整理する。

基本的には、

final point = ore point × multiplier

とする。

============================================================
9. ゲームコマンド
==========

/orerace setup

初期セットアップ。

/orerace start

ゲーム開始。

・ポイント初期化
・タイマー開始
・BossBar開始
・ゲーム状態をRUNNINGに変更
・必要に応じてプレイヤーをスタート地点へ移動
・ゲーム開始演出

/orerace stop

ゲームを強制終了する。

ランキングを表示する。

/orerace reset

ゲーム状態とポイントをリセットする。

BossBarなども削除する。

/orerace status

現在のゲーム状態を表示する。

・RUNNING / STOPPED
・残り時間
・各プレイヤーのポイント
・採掘数

などを表示する。

/orerace debug

DEBUG MODEのON/OFFを切り替える。

============================================================
10. DEBUG MODE
==============

開発中はDEBUG MODEを用意する。

DEBUG MODE ONの場合、鉱石採掘時に詳細情報を表示する。

例：

[OreRace DEBUG]

Player: crocado
Block: DIAMOND_ORE
Point: +5
Multiplier: x1
Final: +5
Total: 18

Deepslateの場合：

Block: DEEPSLATE_DIAMOND_ORE
Point: +5

DEBUG MODE OFFの場合は大量の情報を表示しない。

============================================================
11. 採掘ログ
========

ゲーム中に採掘された鉱石をログに保存する。

最低限、

・時刻
・プレイヤー
・鉱石種類
・基本ポイント
・倍率
・獲得ポイント

を記録する。

例：

[12:34] crocado : DIAMOND_ORE +5

DOUBLE POINT TIMEの場合：

[29:45] crocado : DIAMOND_ORE +10 (DOUBLE)

============================================================
12. Scoreboard
==============

ゲーム中はScoreboardを利用してプレイヤーごとのポイントを表示する。

例：

ORE RACE

crocado       42
Player2       37
Player3       28

============================================================
13. 鉱石採掘数
=========

プレイヤーごとに鉱石採掘数も管理する。

例：

crocado

Points: 42
Ores: 12

必要に応じて鉱石種類ごとの採掘数も管理する。

============================================================
14. BossBar
===========

ゲーム開始時にBossBarを表示する。

BossBarには残り時間を表示する。

例：

ORE RACE
29:59

ゲーム時間が経過するにつれて残り時間を減少させる。

残り時間が0になったらゲーム終了。

============================================================
15. ランキング
=========

ゲーム終了時にポイント順でランキングを表示する。

例：

ORE RACE RESULT

1. crocado : 52 pt
2. Player2 : 47 pt
3. Player3 : 38 pt

============================================================
16. ゲーム開始時の初期化
==============

/orerace start実行時に、

・全プレイヤーのポイント
・採掘数
・鉱石別採掘数
・ゲームタイマー
・DOUBLE POINT状態

を初期化する。

============================================================
17. スタート地点
==========

将来的にスタート地点を保存できるようにする。

/orerace setup

を実行したプレイヤーの位置をスタート地点として保存する。

ゲーム開始時に必要に応じて、

・clear
・gamemode adventure
・tp
・countdown
・gamemode survival

などを行う。

ただし、ミニテスト段階では実装しない。

============================================================
18. 設定
======

将来的に設定値を変更できる構造にする。

基本設定：

duration = 1800秒

double point time = 30秒

double point enabled = false

鉱石ポイント：

copper_ore = 1
iron_ore = 2
gold_ore = 2
lapis_ore = 3
emerald_ore = 4
diamond_ore = 5

deepslate版も同じポイント。

============================================================
19. データ構造
=========

プレイヤーごとに以下を管理する。

points
ore_count
ore_count::<ore>

例：

{orerace.points::UUID}
{orerace.count::UUID}
{orerace.ore::UUID::diamond_ore}

ゲーム状態：

{orerace.running}

DOUBLE POINT状態：

{orerace.double}

============================================================
20. 重要な設計方針
===========

最初から全機能を実装しない。

必ず段階的に開発する。

Phase 1：
鉱石ブロック破壊イベントを検知できるか確認する。

Phase 2：
対象鉱石を判定できるか確認する。

Phase 3：
鉱石種類ごとにポイントを設定して+1、+2、+5などのポイントを加算できるか確認する。

Phase 4：
Scoreboardにポイントを表示する。

Phase 5：
鉱石採掘数を管理する。

Phase 6：
DOUBLE POINT TIMEを追加する。

Phase 7：
BossBarタイマーを追加する。

Phase 8：
採掘ログを追加する。

Phase 9：
ランキングとゲーム終了処理を追加する。

Phase 10：
setup、スタート地点、ゲーム開始演出などを追加する。

============================================================
21. 最初の開発目標
===========

最初のミニテストでは以下だけを実装する。

/orerace start
/orerace stop
/orerace reset
/orerace status
/orerace debug

ゲーム中に対象鉱石を破壊したら、

1. ブロック破壊を検知
2. プレイヤーを取得
3. 鉱石種類を判定
4. 設定されたポイントを取得
5. プレイヤーにポイントを加算
6. DEBUG MODEなら詳細表示

これだけを確認する。

BossBar
DOUBLE POINT TIME
ログファイル
ランキング
スタート地点
countdown
ゲーム演出

などはミニテストには実装しない。

============================================================
22. 最初のテスト対象鉱石
==============

最初のミニテストでは全鉱石を実装してもよいが、問題切り分けを優先する場合は以下の3種類だけでもよい。

IRON_ORE
GOLD_ORE
DIAMOND_ORE

期待結果：

Iron Ore
+2

Gold Ore
+2

Diamond Ore
+5

動作確認後、Copper、Lapis、Emerald、Deepslate版を追加する。

============================================================
23. 最終目標
========

Minecraftの鉱石採掘を利用して、

「制限時間内にどれだけ高得点の鉱石を効率よく採掘できるか」

を競うレースゲームを完成させる。

既存のMinescript版ORERACEの仕様を引き継ぎつつ、Skript版としてシンプルで管理しやすく、今後機能追加しやすい構造にする。

最初は必ず「採掘 → ポイント加算」が動作することだけを確認してから、段階的に機能を追加する。
